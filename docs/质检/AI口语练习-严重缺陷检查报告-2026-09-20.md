## 1. 结论与严重程度口径

**当前项目仍存在阻止安全多人内测或上线的严重缺陷。** 优先问题是默认身份共享、预算旁路、结束状态被旧请求覆盖，以及删除后正文残留。另有教学评估证据、修订传播、运行上限和服务并发稳定性问题。

本次没有沿用“上次发现就仍然存在”的假设：当前代码已经加入较丰富的教练上下文、自动结束回顾、邀请码校验、音频归属校验，也移除了旧无状态接口。但部分新增路径绕开约束，部分修复仅完成了表面状态，仍需按实际效果验证。

本报告使用产品风险优先级，不使用 CVSS 分值：

- **P0 / 内测阻断**：多人真实数据或收费服务使用前必须处理的身份、费用、停止或删除边界问题。不代表已经发生公网攻击、真实账单损失或用户数据泄漏。

## 4. 逐项证据、影响及验收要求

### F-01：前端共享固定邀请凭证

**触发条件：** 按当前前端与默认邀请配置部署，默认演示凭证仍有效，多位用户使用同一网页。

当前前端请求封装固定使用同一演示邀请码；后端启动时自动种入默认邀请码，初始化没有按真实/演示环境隔离。已有服务端验证确实可以拒绝无凭证请求，但不能把共享凭证变成独立身份。

隔离验证：

- 不带凭证访问会话列表，返回 401。
- 第二个客户端使用当前前端同样的凭证，可以列出第一个客户端创建的会话，详情返回 200。
- 这不是“任意填写不同 user_id 都能越权”，而是“所有网页用户拿到相同身份凭证”。

**影响：** 同一身份下的用户可以相互查看、删除练习、共享记忆设置与额度。默认凭证随前端暴露，不能作为个人访问秘密。若已经手动撤销默认凭证，应另行核验部署状态；本次没有检查实际邀请表内容，不声称真实用户已经泄漏。

代码位置：

- [前端固定凭证](../../frontend/lib/api.ts#L3)
- [默认邀请及初始化](../../backend/app/core/auth.py#L8)
- [应用启动时种入默认邀请](../../backend/app/main.py#L43)

修复方向及验收：

1. 每位受邀用户使用服务端验证的独立身份，不在前端包中固定共享凭证。
2. 默认邀请仅限明确隔离的演示环境，真实数据环境不得默认启用。
3. 使用 A/B 两个用户验证会话、音频、记忆、删除与额度均隔离；B 知道 A 的资源标识也不可访问。
4. 无凭证、伪造、过期或撤销凭证被拒绝，切换身份后不残留上一用户数据。

### F-02：提示接口绕过预算控制

**触发条件：** 用户对未结束会话请求提示；项目、用户或会话预算不足时同样适用。

`request_hint()` 直接调用教练和 TTS，不走预算预留或结算；`skip_practice()` 的教练/TTS 路径也没有相同护栏。旧无状态接口虽然已经移除，但新增业务接口形成了新的旁路。

隔离验证：

- 创建会话后把项目预算上限设为零。
- 普通回答被 `BUDGET_EXCEEDED` 拒绝。
- 连续三次提示请求均返回 200。
- 项目账本在三次提示前后均为 spent=0.10、reserved=0.00，没有记录这些调用。

**影响：** 真实模式下，提示会产生模型与语音费用，却不受应用账面额度阻断。用户可反复触发，不能把 PRD 的每日费用上限视为已实现。本次没有发起真实调用，未核算实际损失。普通受控回合仍按名义金额结算，也未证明真实费用硬上限有效。

代码位置：

- [提示调用路径](../../backend/app/services/session_svc.py#L626)
- [跳过跟读调用路径](../../backend/app/services/session_svc.py#L591)
- [普通回合名义费用结算](../../backend/app/services/session_svc.py#L364)

修复方向及验收：

1. 列出全部计费入口并接入统一预算、限次、超时、结算和审计规则。
2. 预算为零时，普通回答、提示、跳过及其他计费入口均不得调用提供者；用调用计数器验证为零。
3. 按可验证的计费上界预留、实际用量结算；名义固定金额只可用于演示。
4. 用户取消不等于供应商不收费；计费未知应保守标为待核对，不能随意退款。

### F-03：结束会话被迟到请求重新开启

**触发条件：** 一个回答请求已经开始，外部评估尚未返回；此时另一连接/标签页结束同一会话，之后原请求继续执行。

隔离验证使用受控慢评估器与两个独立数据库会话，不依赖真实网络：

1. 回答请求读取会话状态并预留额度，然后等待评估结果。
2. 另一连接执行结束，会话与接口结果均为 ENDED，并生成当时的回顾。
3. 释放原评估请求后，它继续生成回复并把会话写为 PRACTICE。
4. 数据库最终出现 status=PRACTICE，但 end_reason=user_ended；新增用户回合与旧回顾不一致。

**影响：** 用户停止不可靠，结束后还可能追加训练和费用；报告与训练事实脱节。前端当前还在 busy 时禁用结束按钮，但这不能阻止跨标签页/接口竞态，只会限制正常退出。

代码位置：

- [回合入口只检查一次状态](../../backend/app/services/session_svc.py#L233)
- [外部调用后写入状态](../../backend/app/services/session_svc.py#L330)
- [结束会话](../../backend/app/services/session_svc.py#L492)
- [处理中禁用结束按钮](../../frontend/app/practice/%5BsessionId%5D/page.tsx#L458)

修复方向及验收：

1. 建立后端终态保护、请求幂等和状态版本校验；不能仅通过前端禁用提交防并发。
2. 处理中仍允许用户结束，取消可取消的调用；不可取消的迟到结果不得继续生效。
3. 重跑上述并发顺序，确认最终仍为 ENDED，无新增教学任务，回顾和费用状态可解释。
4. 补充暂停、重复提交、删除时请求尚未完成等相邻场景。

### F-04：删除全部成功后正文仍留存

当前使用 `query(Session).delete()` 批量删除会话，不触发逐个 ORM 实体的关系级联；当前数据库定义也没有提供对应的数据库级联删除保障。删除函数没有移除关联音频文件。

| 检查项 | 删除后的值 |
| --- | --- |
| 接口响应 | 200 |
| 该测试身份的会话数 | 0 |
| 回合记录数 | 14 |
| 事件记录数 | 5 |
| 上传录音文件数 | 1 |
| 生成音频文件数 | 14 |

这些数量来自合成测试数据，不是实际用户数据规模。回合记录包括用户回答与 AI 回复；列表为空不代表正文已删除。

此外，`cleanup_stale_uploads()` 虽然定义了兜底逻辑，但当前代码未调用它或配置相应调度。现有清理主要依赖手动结束路径，且只针对 uploads 目录，不能据此保证异常退出及全部副本按期限清理。

**影响：** 删除承诺与实际不一致，隐私数据及文件可能持续残留。残留不自动等于可通过现有普通接口读取，但仍属于持久数据未删除。

1. 明确单条与批量删除的全部数据关系，删除正文、评价及无支持的派生记忆；日志按既定政策处理。

### F-05：评估器拿错当前问题

**触发条件：** 用户进入第二轮及后续普通对话，AI 的上一回复存放在用户回合的 reply_text 中。

`_last_coach_text()` 只查询 input_type=coach；普通回答对应的 AI 回复并不保存为单独的 coach 行，因此被遗漏。`_recent_history()` 也只取普通回合的用户文本，没有把对应 AI 回复一起加入。

隔离验证：

- 第一轮教练已提出新的追问。
- 第二次评估收到的 question 仍等于开场问题，不等于第一轮实际追问。
- 验证捕获的是实际传入评估器的内容，而不是仅检查参数中有没有 question 字段。

**影响：** AI 可能把用户对追问的回答当成另一道题来评分，造成无关追问、误判和错误完成声明。Mock 能够依靠简单文本规则通过测试，不能证明真实语义判断正确。

代码位置：

- [当前问题读取](../../backend/app/services/session_svc.py#L138)
- [历史构造](../../backend/app/services/session_svc.py#L148)
- [评估输入](../../backend/app/services/session_svc.py#L262)

修复方向及验收：

1. 统一双方消息和问题引用规则，保证每个回答对应其实际被问的问题。
2. 构造三轮不同追问，逐轮捕获评估和教练上下文，确认双方历史、当前题目与页面一致。
3. 覆盖提示、跟读、跳过和复测，不使用最初开场兜底替代所有当前问题。
4. 真实教学质量另做人工抽查，本项入参修复不自动代表教学已合格。

### F-07：时限未执行，失败额度未释放

本项包含同一运行控制链中的两处已复现问题。

### F-08：同步服务调用阻塞异步接口

**触发条件：** 当前 async 路由直接调用同步会话服务，而服务内执行耗时模型、TTS、WebSocket 评测或转码。

创建会话、提示及跟读等路由存在这一形态。普通 SSE 回合使用同步生成器的执行路径不同，不能笼统声称所有接口都以相同方式阻塞。

隔离验证：

- 在创建会话的教练提供者中注入 350 毫秒同步延迟。
- 同一个异步事件循环中安排约 30 毫秒后执行的任务。
- 该任务实际约 382 毫秒才执行，创建会话接口最终仍返回 200。

这是调度机制验证，不是实际供应商延迟基准，也不是生产并发容量测试。

**影响：** 当前单进程服务里，一个慢外部请求会拖住该进程事件循环上的其他请求，包括用户控制操作。增加机器或切换数据库不能直接消除这一调用方式的问题。

代码位置：

- [异步创建路由直接执行同步服务](../../backend/app/api/routes.py#L58)
- [异步跟读路由](../../backend/app/api/routes.py#L116)
- [会话内同步教练/TTS 调用](../../backend/app/services/session_svc.py#L196)

修复方向及验收：

1. 使用适当的异步调用或受控线程/任务执行方式隔离阻塞操作，并设置并发限制与截止时间。
2. 用慢提供者测试：一个用户等待模型时，另一用户的读取、结束及必要控制请求仍能及时响应。
3. 请求取消和迟到结果处理与 F-03 一起验收，不把换成后台执行当作终态保护已完成。
4. 最后在真实服务和约定并发条件下验证时延与失败率。

## 5. 为什么现有测试全部通过仍有问题

现有用例主要证明单次、顺序、Mock 条件下的接口返回和基本字段，没有覆盖全部业务效果：

- 删除全部测试验证接口成功和会话列表为空，没有检查回合正文、文件及事件残留。
- 修订测试验证 revision_version 和 Turn.eval_result，没有验证评估表、子目标、回顾和后续模型上下文。
- 结束后提交测试验证“先结束再发新请求”，不覆盖“请求已在执行时结束”的并发顺序。
- 身份隔离测试验证两个不同邀请码之间的拒绝行为，不覆盖所有浏览器实际硬编码使用同一邀请码。
- 预算测试覆盖普通回合，没有覆盖提示和跳过等新增计费路径。
- Mock 教学规则不依赖实际问题语义，容易掩盖“问题字段存在但内容错误”。

建议将每项缺陷对应的定向验证转为可重复回归测试；保留既有测试，不用删除用例或放宽断言代替修复。

## 6. 推荐修复顺序及验收记录

1. **先堵身份与费用旁路：F-01、F-02。** 在此之前不建议收集多人真实练习数据或开放真实计费服务给多人使用。
2. **修复终态与删除：F-03、F-04。** 与故障/并发用例一起验证，保证用户停止和删除确实生效。
3. **修复教学证据：F-05、F-06。** 保证当前问题、有效回答和完成结论一一对应。
4. **补齐运行控制与并发响应：F-07、F-08。** 再进行真实时延、成本和综合内测验证。
