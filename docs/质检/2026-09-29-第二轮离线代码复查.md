## 仍开放的代码问题

1. **P0：独立掌握判断不可信。** `review_queue.submit_retest` 只要求输入长度至少 8 字符且未用提示，任何无关英文句子也能两次后变成 `mastered`。`daily_review_svc._judge` 和 `drill_svc._judge` 只看词重合度，同样不能证明与题目相关或完成意图；文字输入还可能被计入口语独立证据。现有用例甚至用酒店回答复测面试来源并预期掌握。按 PRD §10，应让同一结构化评估同时校验题目、意图、帮助、输入模态和来源版本，并用真实样例人工打分校准；在此之前不能把这些指标当成可靠教学结论。
2. **P0：创建会话和提交回合缺用户意图幂等键。** 重复点击或网络重试可生成两个会话/回合、重复调用供应商并记费。队列和语块卡已有按来源去重，但不覆盖核心付费入口；今日复练在待练集合变化时也可另建活动会话。按 PRD §9.3，需要持久化幂等键、请求摘要和结果，并在并发下加唯一约束；这会涉及数据库迁移和接口字段。
3. **P0：预算护栏仍是估算，不能称硬成本上限。** 默认每次 `settle` 记 ¥0.10，旧冒烟约 ¥0.127/回合，超时重试也可能额外收费。账本没有供应商实际用量或费用，`(scope, scope_key)` 缺唯一约束；并发创建预算行及结算也缺足够的数据库级保证。扩大内测前需要以实际用量结算、按最高可花费额预留，并对预算键建立唯一约束与并发测试。
4. **P1：跨会话记忆没有逐回合来源。** 修订或删除本会话时会保守撤销候选，但已合并到别的会话的记忆及 `evidence_count` 无法精确回滚。应增加来源关系与版本，再重算合并记忆。参见上一轮复查记录。
5. **上线前：固定演示邀请码仍由服务启动自动注入。** 当前仅适合本地/受控内测；正式部署前关闭默认种子，换独立分发凭证并验证撤销。

以上第 1 至 3 项是代码/设计缺口，不能归入“只等真实验证”。本轮没有为它们引入未经校准的付费语义评估、接口兼容变更或数据库迁移。
