# 阶段 2.1 技术开发文档｜最小语音回合切片

> 配套文档：《AI口语练习PRD-v0.1.md》（正文 v0.4）、通用技术栈手册、《技术适配声明》。
> 本文档只覆盖阶段 2.1。开发时不得提前实现后续阶段能力（会话落库、跟读评测、回顾、记忆、SSE、Agent 状态机、预算控制均不在本阶段）。

## 一、阶段目标

- 交付范围：一条语音回合端到端跑通——录音上传 → 语音识别（ASR）→ Agent 生成回复 → 语音合成（TTS）→ 播放；同时支持文字输入作为降级入口。
- 阶段产物：
  1. FastAPI 后端：语音回合接口、文字回合接口、音频播放接口；
  2. 最小验收界面（`backend/app/static/index.html`，临时验收工具，非正式产品切片）；
  3. mock 自动化测试（pytest，离线可跑）；
  4. README 启动与验证说明。
- 验收标准：
  - 第一层 mock 测试全部通过；
  - 最小界面能完成"录音 → 看到转写 → 看到回复文字 → 播放 AI 音频"；
  - 第二层真实模型冒烟：有 Key 后跑通一条真实语音回合（无 Key 时如实写"待验"）。
- 明确不做（防止范围蔓延）：会话/历史持久化（SQLite 2.2）、SSE 流式（2.2）、短句跟读发音评测（2.2）、练习回顾（2.3）、学习记忆（2.3）、Agent 目标状态机与预算控制（2.2）。
- 本阶段打通的主链路片段：**录音 → ASR → LLM → TTS → 播放**。

## 二、技术适配摘要

- 开发路径：纵向切片（路径 B），理由见《技术适配声明》第 1 节。
- 采用默认方案：Python 3.12.x + FastAPI + Pydantic + pytest + Git。
- 启用按需模块：本地文件目录 `data/`（音频临时存储，本阶段不落业务库）。
- 偏离/暂缓：SQLite/SQLAlchemy/Alembic、SSE 均推迟到阶段 2.2；正式前端 Next.js 推迟到阶段 3；任务队列规模阈值后再评估。

## 三、技术栈与模型

- 组件：FastAPI、Pydantic、python-multipart（文件上传）、python-dotenv（配置）、pytest、httpx（测试客户端）、uvicorn（本地启动）、dashscope（真实模型 SDK）。
- 不引入：SQLAlchemy、Alembic、Chroma、任务队列、前端脚手架。
- 模型（候选，均通过配置读取；开发期用 mock provider）：
  | 能力 | 候选型号 | 备注 |
  | --- | --- | --- |
  | ASR | 阿里云百炼 paraformer-v2（录音文件识别） | 真实接入方式（本地直传 vs 公网 URL）在真实冒烟时验证并固定，本阶段标记"待验" |
  | LLM | 通义千问 qwen-plus | 面试教练回复 |
  | TTS | CosyVoice（cosyvoice-v1，美式英语音色） | 音色经试听固定，默认 `TTS_VOICE=Lois` |

## 四、环境与配置

- Python：3.12.x（本机已装 `/opt/homebrew/bin/python3.12`），用 `.venv`。
- 配置项（`.env`，不含秘密，模板见 `.env.example`）：
  `PROVIDER_MODE`（mock/real，默认 mock）、`DASHSCOPE_API_KEY`（Key，验收前提供）、`MODEL_ASR`、`MODEL_LLM`、`MODEL_TTS`、`TTS_VOICE`、`MAX_AUDIO_MB`、`MAX_TEXT_LEN`。
- 需要产品经理提供：阿里云百炼 API Key（阶段 2.1 验收前提供即可；现在 mock 推进不阻塞）。
- 启动端口：8000。依赖服务：无（mock 模式完全离线）。

## 六、数据、资产与状态

- 持久化：本阶段为无状态单回合请求-响应，无跨请求业务状态需要恢复；不引入数据库。阶段 2.2 引入 SQLite 持久化会话/任务状态。
- 资产：用户录音存 `data/uploads/{request_id}.{ext}`，合成音频存 `data/audio/{request_id}.{ext}`；文件名由后端生成（`request_id`），不受用户文件名影响，避免路径穿越。本阶段为临时资产，会话内使用；长期清理规则在 2.2 随持久化一并落实。
- 状态机：本阶段无（单回合无状态）。

## 七、API / 工具设计

统一错误结构：`{"error": {"code": "…", "message": "…"}}`，不泄露堆栈。接口前缀集中定义为 `/api/v1`。

| 接口 | 方法/路径 | 请求 | 成功响应 | 主要错误码 |
| --- | --- | --- | --- | --- |
| 语音回合 | POST `/api/v1/turn/voice` | multipart `audio`（音频文件） | `{request_id, transcript, reply_text, reply_audio_url}` | `FILE_TOO_LARGE`、`UNSUPPORTED_AUDIO`、`ASR_*`、`LLM_*`、`TTS_*` |
| 文字回合 | POST `/api/v1/turn/text` | JSON `{text}`（1~2000 字符） | 同上（`transcript` 为空串） | `VALIDATION_ERROR`、`LLM_*`、`TTS_*` |
| 播放音频 | GET `/api/v1/audio/{filename}` | 无 | 音频文件 | `NOT_FOUND`、`BAD_FILENAME` |

校验规则：音频大小 ≤ `MAX_AUDIO_MB`（默认 10MB）；真实类型用文件头魔数识别（webm/wav/mp3/mp4(m4a)/ogg），扩展名与真实类型不符即拒绝；文字长度 1~2000。

本阶段接口为同步请求（单回合 2.5~15 秒量级），SSE 流式在 2.2 引入优化时延。

## 八、Prompt 设计

文件：`backend/app/services/prompts/coach.py`，版本 `v1`。

- 角色：英文面试教练，扮演耐心面试官，围绕"自我介绍"追问。
- 输入变量：`{transcript}`（用户本次表达）。
- 输出格式：纯英文、2~3 句以内、无 markdown、无评分、无标签、不带引号。
- 约束：回应要贴合用户实际说的内容（追问一个相关问题，或对听不懂处自然复述纠正）；用户卡住/沉默时给简短英文提示，必要时附一句简短中文；禁止嘲讽、负面比较、打分；保持场景不跑题。

## 九、验收界面或纵向切片

- 最小验收界面：`backend/app/static/index.html`，临时验收工具（非正式产品切片）。
- 功能上限：录音（MediaRecorder）、文字输入、展示转写/回复、播放回复音频；不做正式视觉与信息架构。
- 目标终端：桌面浏览器（Chrome/Safari）。

## 十、测试要求

### 第一层 mock 测试（pytest，离线必跑）
1. 文字回合返回非空 `reply_text`、`reply_audio_url`、`request_id`。
2. 语音回合（伪 webm 字节）返回 `transcript`、`reply_text`、`reply_audio_url`。
3. 音频文件头非法 → 返回 `UNSUPPORTED_AUDIO`，错误结构为 `{"error":{...}}`。
4. 音频超大小上限 → 返回 `FILE_TOO_LARGE`。
5. 文字为空/超长 → 返回 `VALIDATION_ERROR` 统一错误结构。
6. 播放接口：不存在文件名 → `NOT_FOUND`；含路径穿越（`../`）→ `BAD_FILENAME`；正常文件可播放。
7. 未处理异常兜底返回 `INTERNAL_ERROR`，不泄露堆栈。

### 第二层真实冒烟（有 Key 后必做，本阶段标记"待验"）
- 用一条真实录音跑通"录音→真实 ASR→真实 LLM→真实 TTS→播放"，记录模型、时延、成本；重点验证 ASR 本地文件接入方式。

## 十一、验收清单（产品经理照着点）

1. 打开浏览器访问 `http://localhost:8000/`，看到"AI 口语练习 · 最小验证页"。
2. 点"开始录音"，对麦克风说一句英文自我介绍，点"停止"。
3. 在"你说的"区域看到一句转写（mock 模式是固定示例句）。
4. 在"AI 说"区域看到一句英文回复，并出现可点击的播放条。
5. 点播放能出声音（mock 模式为静音，属预期；真实模式为 AI 语音）。
6. 在文字框输入一句英文点"发送"，也能收到英文回复。
7. 故意上传一个改名成音频后缀的非音频文件，页面显示明确错误提示且不崩溃。

## 十二、风险与待确认项

- 无 Key：真实模型冒烟与 ASR 接入方式为"待验"，本阶段以 mock 通过 + 界面走通为交付边界，不冒充真实模型验证。
- 浏览器录音格式差异（Chrome 产 webm、Safari 产 mp4/m4a），后端魔数识别已覆盖这些格式。
- mock TTS 输出为静音 WAV，仅用于验证链路，不代表真实音色效果。
- 必须由产品经理决定的问题：无。
