# F-01 ~ F-04 修复开发文档（身份 / 费用旁路 / 终态 / 删除）

> 依据：《严重缺陷检查报告 2026-09-20》。本阶段修 4 项 P0 缺陷。

## 一、阶段目标

堵住多人内测前必须解决的 4 个 P0：独立身份、计费旁路、终态覆盖、删除残留。

## 二、各缺陷方案

### F-01 前端共享固定邀请凭证（P0）

- 前端不再硬编码共享邀请码：新增「邀请码登录」——用户输入自己的邀请码，存入本地 `localStorage`，所有请求用该码。
- `lib/api.ts` 改为从本地读取邀请码；提供 `login/logout`；无码时接口 401，首页引导输入。
- 后端新增 `ENABLE_DEMO_INVITES`（默认 true，供本地演示）；真实环境关闭默认邀请、只接受显式创建/分发的邀请码。
- 前端导航显示当前身份，支持「退出」切换。

### F-02 提示/跳过绕过预算（P0）

- `request_hint()`、`skip_practice()` 接入与普通回合相同的 `BudgetGuard.reserve/settle`。
- 预算为零/超额时，这些接口在调用教练/TTS 前拒绝（spy provider 验证调用次数为 0）。

### F-03 迟到请求覆盖终态（P0）

- `submit_turn` 在外部调用（ASR/评估/教练/TTS）之后、写回合之前，`db.refresh(session)` 重新读取状态。
- 若会话已被结束/删除：回滚未提交改动、释放预留、返回 `SESSION_ENDED`/`SESSION_NOT_FOUND`，不写回合、不改状态、不追加费用。
- 补充并发回归测试（受控慢评估器 + 两个 DB 会话）。

### F-04 删除后正文/文件残留（P0）

- 抽出 `_collect_and_delete_session`：删除记忆、评估、事件日志、回合（ORM 级联）、并收集引用音频文件名。
- `delete_session` 与 `delete_all_sessions` 都走该函数，并在提交后物理删除 `data/audio` 中引用文件；同时触发 uploads 清理。
- 删除验证从"列表为空"改为"会话/回合/评估/事件/音频文件 计数均为 0"。

## 三、测试要求

1. F-01：无码 401；输入 A/B 码分别得到独立身份，互不可见；退出后不残留。
2. F-02：预算为零时提示/跳过不触发 provider（计数 0）。
3. F-03：慢评估 + 并发结束，最终状态仍 ENDED，无新增回合。
4. F-04：删除全部后 会话/回合/评估/事件/音频文件 均清零。

## 四、验收清单

按报告第 4 节各缺陷的验收项逐条核对。

## 五、风险与回退

- 邀请码登录为内测临时方案，正式登录（HttpOnly Cookie）在阶段 4。
- 真实并发（PostgreSQL）与真实费用仍需内测验证；本阶段以 SQLite + spy provider 验证边界。
