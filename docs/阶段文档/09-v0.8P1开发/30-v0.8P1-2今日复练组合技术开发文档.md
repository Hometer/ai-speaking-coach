## 1. 范围与不做

### 1.1 本子阶段做

1. 首页新增「今日复练」卡：展示今天到期项目数 + 预计时间；到期不足 3 条也按实际展示（不用未到期凑数）。
2. 「开始今日复练」：从待复练队列选出 3~5 条已到期、来源有效的项目，逐条练习。
3. 每条复练：先回忆表达 → 按需提示 → 完成/跳过/延后/标记有误/退出。
4. 结果写回同一套队列（不创建第二套状态）：
   - 无答案帮助完成换题表达 → 进入下一档间隔；
   - 完成脱稿、换题未完成/未参加 → 保持当前间隔；
   - 用了关键词/半句/完整答案 → 回到 1 天或当前较短间隔；
   - 识别失败/服务故障/退出 → 不记学习失败，保留原到期状态；
   - 用户标记有误 → 暂停任务进入争议处理。
5. 结束汇总：完成数量、帮助程度、下次到期情况。

### 1.2 本子阶段不做（后续子阶段）

- REQ-30 示范与本人录音对比（另做）。
- REQ-31 语块卡（另做）。
- 进步中心新增「脱稿完成数/迁移成功数」指标（放到 P1 收尾统一做）。

## 2. 现状与差距

- 现状：`ReviewQueueItem` 已有 `status/due_at/success_count/retest_result`，`submit_retest` 已实现跨日约束（AC07-08）；首页与「待复练页」只展示队列列表，没有「今日复练组合」这一连续练习入口。
- 差距：没有「选 3~5 条到期项组成一次练习」的组合流程；没有「逐条回忆→提示→完成/跳过/延后」；没有按本次结果推进间隔档位；没有结束汇总。

## 3. 数据模型

复用 `ReviewQueueItem`（不新建队列表），新增组合会话与间隔档位字段（迁移幂等）：

```text
ReviewQueueItem 增列
  interval_days    当前间隔档位天数（1/3/7/14，默认 1）
  help_used        本次复练是否用过答案帮助（关键词/半句/完整；默认空，完成后写回）

Session（复用 practice_type="daily_review" 作为「今日复练」会话）
  daily_review_items  本次组合包含的队列项 id 列表（JSON 文本）
  daily_review_index  当前练到第几条（0-based）
```

`DailyReviewAttempt`（可选，本次每条尝试记录，用于汇总与事件）：

```text
DailyReviewAttempt
  id / user_id / session_id
  queue_item_id     队列项
  attempt_answer    用户回答（脱敏）
  help_used         是否用了答案帮助
  result            completed / skipped / deferred / disputed / failed
  created_at
```

## 4. 后端设计

### 4.1 选择到期项目（确定性）

`GET /review-queue/due-today`（或复用现有 due 逻辑扩展）：
- 只选 `status in (pending, awaiting_retest)` 且 `due_at <= now` 且来源有效（未被争议/删除/转写作废）的项目。
- 排序：逾期时间最早优先 → 是否用过答案帮助（没用过优先）→ 最近一次独立结果。
- 取前 3~5 条（最多 5）；不足 3 条按实际数量，不用未到期凑数（AC08-07）。

### 4.2 开始今日复练（幂等）

`POST /review-queue/daily-review/start`：
- 无到期项 → 返回空列表，不创建会话。
- 有到期项 → 创建 `Session(practice_type="daily_review")`，写入 `daily_review_items`（队列项 id 列表）。
- 幂等：同一批到期项同一日内重复开始返回同一会话，不重复创建/计费（AC08-09）。

### 4.3 逐条练习

`POST /review-queue/daily-review/{session_id}/attempt`：
- 取当前 `daily_review_items[daily_review_index]` 对应队列项，返回「回忆提示」（目标句/中文意图，取决于是否已脱稿过）。
- 提交回答后判定：语义/可理解性为主，同义表达不逐字复现（复用 P1-1 的宽松判定思路）。
- 可选：用过答案帮助（关键词/半句/完整）则 `help_used=true`。

### 4.4 结果写回（同一套队列，推进间隔档位）

按 PRD 6.5 表格：

| 本次结果 | 间隔档位变化 |
| --- | --- |
| 无答案帮助完成换题表达（独立/迁移） | interval_days 进下一档（1→3→7→14） |
| 完成脱稿、换题未完成/未参加 | 保持当前档位 |
| 用了关键词/半句/完整答案 | 回 1 天 |
| 识别失败/服务故障/退出 | 不记失败，保留原到期状态 |
| 用户标记有误 | 暂停任务进争议 |

- 复用 `submit_retest` 的 AC07-08 到期校验：未到期不增加成功次数。
- 第二次独立成功与第一次至少间隔 24h 才「掌握」——确定性服务端校验。

### 4.5 结束汇总

`POST /review-queue/daily-review/{session_id}/end`：
- 汇总本次完成数量、用过答案帮助数量、延后/跳过数量、下次各档到期时间。
- 会话结束，不恢复训练。

## 5. 前端设计

- 首页新增「今日复练」卡：到期数 + 预计时间 + 开始按钮（到期 0 条则显示「暂无到期内容」）。
- 今日复练页：逐条展示「先回忆，卡住再要提示」，按钮：完成/跳过/延后/标记有误/退出；顶部显示进度（第 N/共 M 条）。
- 结束页：完成数量、帮助程度、下次到期情况。
- 复用现有队列页的「掌握/待复测/争议」展示，不另建第二套状态。
