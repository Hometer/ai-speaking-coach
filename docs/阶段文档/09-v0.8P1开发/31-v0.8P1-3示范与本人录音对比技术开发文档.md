## 1. 范围与不做

### 1.1 本子阶段做

1. 单句练习页（跟读/脱稿）把**示范音频**和**本人录音**放在同一练习卡中。
2. 示范支持**正常速度 + 慢速**（慢速用前端播放倍率 0.75x 实现，不额外合成 TTS）。
3. **示范与本人录音互斥播放**：播放一个自动暂停另一个。
4. 支持**重录**，并明确「哪个版本用于当前评价」。
5. 每次评测关联**录音版本、参考句版本、阶梯阶段**。
6. 用户离开或录音清理后，页面显示「录音已清理」；历史页不提供普通录音长期复听。
7. 评测不可用时仍可完成音频对比，页面明确说明「没有发音评测」。

### 1.2 本子阶段不做（后续）

- 波形、逐词标色、词级问题（只有真实服务提供可靠证据才做）。
- 历史页普通录音长期复听（明确不做）。

## 2. 现状与差距

- 现状：跟读（`submit_practice`）已接讯飞短句评测；页面已有示范音频（`practiceDemo`）与结果（`practiceResult`）；用户录音走 `data/uploads` 转写后即清理，不保留回放 URL。
- 差距：没有「本人录音回放」；没有「互斥播放 / 调速 / 重录」；评价没有绑定录音版本；录音清理后无提示。

## 3. 数据模型

- 用户录音落盘到 `data/audio/`（与 TTS 音频同目录，鉴权访问），`Turn` 增加 `recording_url`（本人录音 URL，会话内回放用）。
- `Turn.practice_eval`（JSON）增加 `recording_url / reference_version / drill_stage`，绑定本次评价的录音版本、参考句版本与阶梯阶段。
- 录音用后清理沿用 `cleanup`：会话结束目标 10 分钟、最迟 24 小时删除。

## 4. 后端设计

1. 跟读提交（`submit_practice`）保留用户录音文件：写入 `data/audio/`，返回 `recording_url`，并写入 `Turn.recording_url`。
2. 评测绑定：`practice_eval` 记 `recording_url` + `sentence`（参考句版本）+ `drill_stage`（阶梯阶段，若在脱稿阶梯内）。
3. 录音鉴权：复用 `/api/v1/audio/{filename}` 的归属校验，仅本人可访问。
4. 清理：会话结束/删除时删除 `recording_url` 指向的文件；已清理则前端显示「录音已清理」。
5. 评测失败：`submit_practice` 返回 `eval` 为空/`valid=false`，仍保留录音 URL 供对比，页面提示「没有发音评测」。

## 5. 前端设计

- 单句练习卡：示范音频（正常/慢速切换）+ 本人录音播放 + 录音按钮 + 重录。
- 互斥播放：同一卡内只允许一个音频在播，播放 A 时暂停 B。
- 调速：示范用 `AudioPlayer` 的 `playbackRate`（0.75x）。
- 结果区显示「本次评价使用的录音版本 + 参考句版本 + 阶梯阶段」；录音已清理时显示占位提示。
- 评测失败仍可对比，显示「没有发音评测」。
