## 1. 范围与不做

### 1.1 本子阶段做

1. 有效表达建议可生成一张**轻量语块卡**，字段：来源原句、建议表达、一个主要语块、中文解释、适用情境、可替换部分、一个新例句。
2. 卡片提供「练这一句」和「加入待复练」两个入口。
3. 语块卡**不添加用户未提供的经历、职位、成绩或数字**。
4. 语块卡跟随来源历史的保存期限；来源失效/删除时传播失效。
5. 「加入待复练」只使用选中材料，不读取整份历史（记忆关闭时）。

### 1.2 本子阶段不做

- 独立词典/生词本。
- 单词解释（仅在理解语块需要时给，本阶段先不给，后续按需）。
- 自动开启长期记忆（明确不做）。

## 2. 现状与差距

- 现状：回顾建议（`ReviewItem`）已有「原句 / 建议句 / 中文解释 / 练这一句 / 加入待复练」；场景配置有 `help_materials` 关键词、`variations`、`reference_expressions`。
- 差距：没有「语块卡」这一轻量对象（来源 + 语块 + 解释 + 情境 + 替换 + 新例句）；没有独立的卡片展示页/入口。

## 3. 数据模型

新增 `PhraseCard`：

```text
PhraseCard
  id / user_id
  source_session_id / source_turn_id   来源建议（复用 ReviewItem 来源）
  original_text       来源原句
  suggestion_text     建议表达
  chunk_text          主要语块
  explanation_zh      中文解释
  context_zh          适用情境
  replaceable         可替换部分
  example_text        新例句
  status              active / invalid（来源失效/删除传播）
  created_at
```

- 复用 `ReviewQueueItem`：加入待复练仍走现有队列，同一来源只保留一条有效记录（AC08-17）。
- 来源失效/删除传播：源会话删除或建议争议/转写作废时，`PhraseCard.status=invalid`，并传播到队列（现有 `invalidate_by_turn` 扩展）。

## 4. 后端设计

### 4.1 语块卡生成（确定性，不编造用户事实）

从来源建议 + 场景配置生成，**不用模型扩写用户经历/职位/成绩/数字**：

- `chunk_text`：从建议句提取主要语块（场景 `help_materials.keywords` 中命中建议句的关键短语）。
- `explanation_zh`：来源建议已有 `explanation_cn`（或场景 `goal_zh`）。
- `context_zh`：场景 `variations` 之一（适用情境）。
- `replaceable`：把 `chunk_text` 用场景 `keywords` 中的另一关键词替换。
- `example_text`：场景 `reference_expressions` 中与建议句不同的另一句（新例句）。

### 4.2 接口

- `POST /api/v1/phrase-cards`（`{source_session_id, source_turn_id}`）：幂等生成/返回语块卡。
- `GET /api/v1/phrase-cards`：列表（仅当前用户、状态 active）。
- 加入待复练：复用现有 `POST /review-queue`（同一来源幂等，AC08-17）。
- 练这一句：复用 `POST /sessions/practice-sentence`（脱稿阶梯，P1-1）。

## 5. 前端设计

- 回顾页每条建议旁增加「语块卡」入口；语块卡页展示：来源原句、建议表达、主要语块（高亮）、中文解释、适用情境、可替换部分、新例句。
- 卡片底部「练这一句」「加入待复练」按钮。
- 来源失效时显示「已失效，待复核」。

## 6. 验收标准（AC08-14 ~ AC08-17）

| 用例 | 可观察通过条件 |
| --- | --- |
| AC08-14 | 语块卡包含来源、解释、情境、替换部分和新例句 |
| AC08-15 | 语块卡不添加用户未提供的经历、职位或成绩 |
| AC08-16 | 记忆关闭时加入复练只使用选中材料，不读取整份历史 |
| AC08-17 | 一条来源只保留一条有效队列记录，阶梯结果写回原项目 |
