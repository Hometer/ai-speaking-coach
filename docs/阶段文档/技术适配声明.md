# 技术适配声明

> 项目：AI 口语练习（MVP 单场景）
> 日期：2026-09-18
> 依据：`docs/PRD/AI口语练习PRD-v0.1.md`（正文 v0.4 质检修订稿）+《通用技术栈手册》

## 1. 产品形态判断

- 产品类型与核心任务：网页端 AI 口语教练。Agent 在"英文面试自我介绍"单场景内，与 18 岁以上受邀内测用户进行回合制语音/文字对话，动态选择教学行动（追问 / 提示 / 短句跟读 / 换题复测），结束后给出有证据的反馈。
- 核心交互：多轮对话（回合制）+ 动态工具调用（ASR、TTS、发音评测、训练材料检索、训练评估、记忆读写）。
- 开发路径：**纵向切片（路径 B）**。理由：本产品核心价值（敢开口、有对话伙伴）依赖语音交互本身，仅靠 JSON 无法判断"用户说话后能否得到合理转写、收到场景一致的语音回复"，必须尽早跑通一条真实语音回合。
- 当前阶段范围：阶段 2 后端 MVP 的第 1 个子阶段——最小纵向切片：一条语音回合端到端（录音上传 → ASR → Agent 生成 → TTS → 播放），配最小验收界面。

阶段 2 子阶段规划（CTO 推荐拆分，供产品经理了解，不用做选择）：

| 子阶段 | 内容 |
| --- | --- |
| 2.1 最小语音回合切片 | 录音上传 → ASR 转写 → Agent 生成回复 → TTS 合成 → 播放（文字+音频）+ 最小验收界面 |
| 2.2 Agent 教练 + Harness + 持久化 | 目标状态机、工具调用约束（≤3 次/回合、重试≤1、预算/停止规则）、独立完成评估分离、短句跟读评测、SQLite 落库（用户/会话/回合/评估） |
| 2.3 回顾/历史/记忆 + 降级 + 达标验证 | 练习回顾、历史查看与删除、记忆（默认关闭）、故障降级、时延与成本达标测量 |

## 2. 采用的默认方案

| 项 | 方案 | 采用原因 |
| --- | --- | --- |
| 后端语言 | Python 3.12.x（.venv） | 手册默认，与线上运行时一致 |
| 后端框架 | FastAPI | 能力可测试、可调用 |
| 数据校验 | Pydantic | 校验接口与模型结构化输出 |
| 测试 | pytest | 自动化检查业务与错误路径 |
| 代码管理 | Git | 强制底线，可恢复、可审查 |
| 模型调用 | 官方 SDK（阿里云百炼 DashScope；讯飞评测接口） | 手册默认 |
| 前端终端 | Web 网页（桌面优先，移动端保持基本可读） | PRD 第 13.1 节 |
| 正式前端栈 | Next.js + TypeScript + Tailwind CSS | 手册 Web 默认，阶段 3 启用 |
| 阶段 2 验收界面 | 单 HTML 挂 `backend/static/`，原生 JS + fetch/SSE | 手册"最小验收界面"默认 |

## 3. 触发的按需模块

| 模块 | 触发需求 | 当前阶段是否引入 |
| --- | --- | --- |
| SQLite + SQLAlchemy + Alembic | 用户/会话/回合/评估/记忆等多实体关系、用户账户、历史查询 | 阶段 2.2 引入（2.1 先验证链路，不落库） |
| SSE | PRD 要求流式请求优化回合响应 | 阶段 2.2 引入 |
| 本地文件目录 `data/` | 音频大文件存储（临时录音） | 阶段 2.1 引入 |
| 对象存储 | 生产环境评估 | 阶段 4 再评估 |
| 任务队列 | 长耗时任务 / 高并发 | 暂缓，短请求单进程够 |
| Chroma / python-docx / pypdf / OCR | RAG、Word、PDF、扫描件 | 均不引入（无对应需求） |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代/处理 | 原因 | 影响 | 重新评估条件 |
| --- | --- | --- | --- | --- |
| Python 3.12（本机现为 3.9.6） | 阶段 2 开工前升级到 3.12 并建 `.venv` | 手册要求与线上运行时一致 | 无功能影响，仅本机环境 | 无需 |
| 正式前端 Next.js | 阶段 2 先用单 HTML 验收界面，正式前端留到阶段 3 | 核心链路未验证前不过早铺正式界面 | 阶段 2 界面朴素，属预期 | 阶段 2 链路验收通过后 |
| 企业认证上线 | 个人身份先走临时方案（单实例、可能丢几分钟数据、不能扩容） | 产品经理已确认（D9 选 B） | 仅影响阶段 4 部署形态 | 阶段 4 前确认是否补企业认证 |
| 任务队列 | 暂缓 | MVP 短请求为主 | 高并发时需排队 | 达到规模阈值时 |

## 5. 强制底线检查

- 密钥与隐私：**通过**。密钥走 `.env`（已在 `.gitignore`），不在对话、日志、前端产物、提交记录中回显。
- 数据与任务可恢复：**计划中**。阶段 2.2 引入 SQLite 持久化会话/任务状态，进程重启可恢复；阶段 2.1 最小切片暂不依赖落库，验收点前补齐并实际验证。
- 输入输出校验：**通过**。Pydantic 校验 + 模型结构化输出校验。
- 错误与日志边界：**通过**。统一错误结构 `{"error":{"code","message"}}`，日志不记密钥、正文、完整音频。
- 测试与真实模型验收：mock 自动化测试（pytest）先行；真实模型冒烟在验收前执行，无 Key 时如实写"待验"，不冒充通过。
