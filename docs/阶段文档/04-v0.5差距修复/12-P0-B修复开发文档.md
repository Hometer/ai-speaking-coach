# P0-B 修复开发文档（GAP-13 ~ GAP-16）

> 依据：PRD v0.5（REQ-12/13/14/15）、差距清单 v0.5。本阶段修内测边界 4 项。

## 一、阶段目标

在多人真实数据内测前建立边界：可信身份与音频访问（GAP-13）、旧接口统一护栏（GAP-14）、预算/并发/终态保护（GAP-15）、数据生命周期兜底清理（GAP-16）。

## 二、各 GAP 方案

### GAP-13 可信身份与音频访问（REQ-12）

- 新增 `Invite` 表：`code`（唯一）、`user_id`、`revoked`。初始化时内置两个测试邀请码，分别映射独立测试身份（如 `test-a`→`user-a`、`test-b`→`user-b`），不共用 demo-user。
- 请求身份由 `X-Invite-Code` 头提供邀请码，服务端查表推导 `user_id`；无效/撤销码拒绝（401）。不再信任客户端填写的任意 `X-User-Id`。
- 音频访问：`/api/v1/audio/{filename}` 改为按 Turn 归属校验——找到引用该音频的回合→会话→用户，归属不一致拒绝（403），未引用拒绝（404）。
- 前端：`lib/api.ts` 的固定 `UID` 改为发送邀请码（内测前由产品经理分发）。

### GAP-14 旧接口统一护栏（REQ-12/13/14）

- 删除无状态旧接口 `POST /api/v1/turn/voice`、`POST /api/v1/turn/text`（绕过会话预算与身份），其能力已由会话接口覆盖。
- 保留并加固 `/api/v1/audio/{filename}`（纳入 GAP-13 归属校验）。
- 核对：正式前端已用会话接口，临时验收页不再使用旧接口，删除不影响现有客户端。

### GAP-15 预算、故障与终态保护（REQ-07/13/14）

- 原子预留：`BudgetGuard.reserve` 改为「条件更新 + rowcount 校验」——`UPDATE ... SET reserved=reserved+? WHERE spent+reserved+? <= cap`，rowcount=0 即超额拒绝，避免并发共同突破。
- 失败释放：会话内异常路径对已预留额度做补偿（`settle` 释放）；不重复计费。
- 幂等：回合落库前先查 `turn_id` 是否已存在，重复提交不双份保存/计费。
- 终态保护：ENDED/PAUSED 状态在入口拒绝；迟到响应不覆盖终态（已由状态检查保证，补测试）。

### GAP-16 数据生命周期与兜底清理（REQ-15）

- `cleanup_old_uploads` 扩展为同时清理原始上传与转码副本（`uploads/*.wav`、`uploads/*`）。
- 触发路径：手动结束、自动达标结束时调用；另提供按最后活动时间兜底（最迟 24h），供后续定时任务接入。
- 配置：`UPLOAD_RETENTION_MINUTES`（默认 10）、新增 `UPLOAD_MAX_AGE_MINUTES`（兜底，默认 1440）。
- 文本/回顾/记忆 30 天、质检录音 7 天等期限作为配置保留，正式定时任务在部署阶段接入（本阶段完成清理函数与触发，不含后台定时器）。

## 三、数据模型变更

- 新增 `Invite` 表；开发库重建（仅 mock 数据）。

## 四、测试要求

1. 身份：无凭证/伪造码 401；A/B 两身份互访会话/记忆/音频被拒；音频归属校验。
2. 旧接口：删除后调用返回 404，且不触发 provider（spy 验证调用次数 0）。
3. 预算：临界余额并发不突破（SQLite 串行 + 条件更新）；失败释放预留；重复回合不双份计费。
4. 清理：过期上传与转码副本被删、未过期保留。

## 五、验收清单

1. 无/伪造邀请码访问会话或音频被拒绝。
2. 两个独立身份不能互看会话、记忆、音频。
3. 旧接口不可用且不触发模型调用。
4. 预算在临界余额并发下不超支。
5. 异常退出后，过期录音有兜底清理路径。

## 六、风险与回退

- 并发测试在 SQLite 下为串行语义，条件更新保证不超支；生产并发以 PostgreSQL 再验证。
- 邀请码为内测临时方案，正式登录（HttpOnly Cookie 会话）在阶段 4。
