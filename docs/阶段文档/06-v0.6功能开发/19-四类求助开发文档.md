# 四类求助开发文档（v0.6 · REQ-03/05/06）

> 依据：PRD v0.6 第 6.6.1 节。本阶段只做"四类求助"，不含练这一句、数据边界（后续批次）。

## 一、阶段目标

把单一「提示」升级为四类求助：没听清 / 没听懂 / 不会组织回答 / 中文转英文；组织类渐进帮助；帮助类型可记录、可影响完成判断。

## 二、数据模型变更

- `Turn` 增加 `help_type`（String：repeat/explain/organize/translate，默认 ""）、`help_level`（Integer：organize 渐进级别 1 关键词/2 半句/3 完整示例，默认 0）。

## 三、后端方案

### 求助接口

- 新增 `POST /sessions/{id}/help`，请求 `{help_type, level?}`；响应含 `reply_text`、`reply_audio_url`、`action_type`、`help_type`、`help_level`。
- 复用 `BudgetGuard`（同 F-02，预算/失败释放）；帮助绑定当前问题；会话已结束/暂停拒绝。

### Mock 教练帮助内容（按类型）

| help_type | level | 行为 |
| --- | --- | --- |
| repeat | — | 重播当前问题（复用当前问题文本，不生成新答案） |
| explain | — | 当前问题的中文解释/简单英文重述，不给答案 |
| organize | 1 | 贴合当前问题的关键词 |
| organize | 2 | 半句提示 |
| organize | 3 | 完整参考说法（明确"参考说法"） |
| translate | — | 接受中文，给保留原意的简单英文 |

### 完成判断（REQ-06）

- 评估上下文传入最近帮助类型：`organize`（答案辅助）→ 该次回答判 `hinted`；`explain`（理解辅助）→ 记录为理解辅助，不判无辅助独立；`repeat`（播放支持）→ 不直接判语言失败。
- 帮助事件按顺序记录，一次重播不清除之前的答案提示。

## 四、前端方案

- 对话页「💡 提示」改为「需要帮助」，点击展开四个选项；"不会组织"再逐级展开关键词→半句→完整示例。
- 保留"给点提示"快捷文案（等同于打开分类选项）。
- 显示帮助内容气泡（复用消息流）。

## 五、测试要求

1. 四类求助各自返回对应内容与 help_type/level。
2. organize 渐进：level 1/2/3 内容不同，记录有序。
3. 帮助后（organize）下一次回答判 hinted，不判 independent。
4. 预算为零时求助被拒，不调用提供者。
5. 会话结束后求助被拒。

## 六、验收清单

1. 对话页四类求助入口可用，各返回正确帮助。
2. 组织类渐进（关键词→半句→示例）。
3. 帮助类型被记录，organize 后的回答不判独立完成。
