## 1. 修复 1：语音证据只能来自语音端点

- 删除 `RetestRequest`、`DailyReviewAttemptRequest`、`DrillAttemptRequest` 的 `input_type` 字段。
- `submit_retest` / `submit_attempt` / `submit_drill_attempt` 的 `input_type` 参数默认且仅服务端设为 `"text"`；路由不再传客户端字段。
- 三条 voice 端点（`retest/voice`、`daily-review .../voice`、`drill-attempt/voice`）继续走 ASR，内部传 `"voice"`，是唯一能形成语音证据的路径。

## 2. 修复 2：迁移需场景相关性

`judge_transfer(answer, original, input_type, help_shown, scene_keywords)`：

- 语音 + 非照抄原句 + 至少 3 词，且回答与场景关键词（acceptable_points / 参考表达）有内容词重叠才 `transfer`；否则 `pending`（无法判断，不升级）。

`drill_svc` 传入当前场景关键词。

## 3. 修复 3：幂等真正查重

- `ReviewQueueItem` 增 `last_attempt_key`；`submit_retest` 若 attempt_key 与上次一致且内容一致，返回当前状态；同键不同内容 409。
- `submit_drill_attempt` / `submit_attempt`：若该会话已存在同 attempt_key 的尝试，返回首次结果（不重复推进/计费）。

## 4. 修复 4：七日计划入口

- 首页 `Home` 读取 URL `?scene=` 并设为当前场景；计划页「练这一场景」链接带 `?scene=`。

## 5. 修复 5：预算实际花费

- 真实模式：`submit_turn` 用 `generation_call.get_last_usage()` 的 token 数 + TTS 字符，按参考单价换算 `actual_spent`，调用 `BudgetGuard.settle_actual`。
- mock 模式：不伪造，`actual_spent` 保持 0。

## 6. 测试计划

- 后端 Mock 回归保持通过（当前 147/147），新增：
  - 文字 JSON 带 `input_type=voice` 不再升级独立（伪造被拒）。
  - 无关句换题不迁移（返回 pending）。
  - 同 attempt_key 重放返回首次结果；同键不同内容 409。
  - 计划「练这一场景」带 scene。
  - settle_actual 在真实路径被调用（离线假 SDK 计数）。
- 前端 typecheck / lint / 组件测试 / build 通过。
