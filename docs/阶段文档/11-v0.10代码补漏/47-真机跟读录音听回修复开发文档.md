## 1. 现象与根因

产品经理在安卓 Chrome 可进入跟读并提交录音，但提交后看不到「你的录音」播放器。当前页面仅在 `practiceSentence` 非空时渲染听回播放器；提交成功同时清空 `practiceSentence`，因此成功路径立刻隐藏整个练习卡。后端已经保存 `recording_url`，但会话详情响应模型未声明该字段，刷新时会被过滤。这是前端展示与接口响应两个本地缺口。

## 2. 修复范围

1. 跟读提交后，在当前会话保留「刚才的跟读」区域，展示本次参考句、示范音频、本人录音及评分说明；无需继续保持输入卡或阻断教练下一问。
2. 会话详情的跟读回合返回 `recording_url`；按现有音频接口做归属校验。刷新后从会话已保存的跟读回合恢复最近一次录音及对应示范；录音过期或已清理时沿用现有播放器的失效提示。
3. 维持 Mock 与真实服务的证据边界：Mock 示范静音、评分为示例；不能据此宣称教练真实播报或讯飞词级通过。
4. 只改展示，不修改音频接口、保存期限或历史普通录音规则。

## 3. 验证

- 前端类型检查、Lint、构建通过；浏览器在 Mock 会话触发跟读、提交录音后能看到本人播放器，刷新后仍能看到；播放失败时有提示。
- 后端仍执行既有 Mock 回归；安卓 Chrome 本人听回的结果由产品经理补充，未收到前保留待验。

## 4. 修复结果与阶段状态

前端将最近一次跟读录音展示在独立的「刚才的跟读 · 可听回」区域，提交后不随输入卡消失；刷新时从会话回合恢复。后端 `TurnItem` 响应模型补 `recording_url`，原有音频接口继续按用户归属校验。后端全量 Mock 165/165、前端 typecheck/lint/build 通过；浏览器 Mock 模拟提交与刷新后均看到播放器，刷新后音频接口返回 200（32044 字节）。截图见 `docs/evidence/阶段3-v0.10本地收口/跟读录音听回-桌面Mock.png`。

产品经理随后在安卓 Chrome 刷新临时 HTTPS 页面，重新提交跟读并点击「你的录音」，反馈能听到自己的声音。此项是本人真机确认，尚无手机截图。真实语音转写、教练播报、讯飞词级、iPhone Safari 和供应商费用仍按证据包待验。
