## 1. 核心设计决策

### 1.1 统一"学习证据"判定口径

现状：队列复测用 `len(answer)>=8`，脱稿/今日复练用"与目标句词重叠 ≥0.4"——都不能证明回答相关、未用答案、是语音。

本批改为**四条件共同决定**是否升级独立/迁移/掌握：

1. **输入模态**：`input_type=voice` 才能形成"口语独立/迁移/掌握"；`text` 只能记为"文字完成"（非独立）。
2. **帮助证据**：帮助是否已用由服务端记录决定，客户端 `hint_used/help_used` 字段只作参考、不单独采信。
3. **语义相关**：用统一的结构化评估（mock 用确定性规则，real 用评估器）校验回答与当前题目/意图相关并完成主要意图；"无法判断"时不升级。
4. **来源版本**：绑定题目版本、参考句版本、录音版本、评估版本；任一失效则不得升级。

### 1.2 文字与语音分开计数

沿用 PRD §10.1/§10.3：文字回答可以给表达反馈，但不产生"口语独立""脱稿完成""迁移""掌握"。本批在队列/脱稿/今日复练的提交接口增加 `input_type`，服务端据 `input_type` 区分"文字完成"与"口语独立"。

### 1.3 确定性"无法判断"兜底

mock 下无法可靠判断语义相关时（例如无关句但词有重叠），返回"待判断"，不升级成功次数/间隔/掌握。real 下用评估器结果，评估器不可用时同样不升级。

## 2. 数据模型变更（`entities.py` + `database.py` 幂等迁移）

1. `ReviewQueueItem`：增加 `meaning_zh`（中文意图/场景线索，用于隐藏答案时提示）；`help_shown`（服务端已展示帮助标记）；`last_input_type`（上次复测输入模态）；`attempt_key`（幂等键）。
2. `DrillAttempt`：增加 `input_type`、`question_text`（本次题目）、`reference_version`（参考句版本）、`help_shown`、`attempt_key`。
3. `DailyReviewAttempt`：增加 `input_type`、`help_shown`、`attempt_key`。
4. `Session`：增加 `request_key`（创建会话幂等键）、`in_flight`（处理中标记）、`idle_timeout_seconds`（空闲收尾）。
5. `Turn`：增加 `request_key`（提交回合幂等键）。
6. `Memory`：增加 `source_turn_id`、`version`、`expires_at`。
7. `BudgetLedger`：`(scope, scope_key)` 增加唯一约束；增加 `estimate_spent`（估算）与 `actual_spent`（实际用量）分列。
8. `QualityLabel`：`issue_type` 增加合法值校验（代码层）；增加 `source_exists` 校验逻辑。
9. `PracticeEval`（Turn 上 `practice_eval` 已是 JSON 文本）：结构增加 `word_items`、`reference_version`、`recording_version`。

迁移沿用 `migrate_db`（幂等加列、加唯一约束需处理存量重复后再建约束）。

## 3. 分条改动设计

### AC10-01 待复练证据（`review_queue.py`、`schemas/review_queue.py`、`queue/page.tsx`）

- `list_queue` / `_to_dict` 不再返回 `suggestion_sentence` 作为默认答案；改为返回 `meaning_zh`（无则取来源场景 `goal_zh`）与"是否已展示帮助"。
- 新增 `POST /review-queue/{item_id}/reveal`：用户显式"看答案"时服务端落 `help_shown=True` 并返回完整句。
- `submit_retest` 改签名：`(db, user_id, item_id, answer, input_type, attempt_key)`；不再采信客户端 `hint_used`。
  - `help_shown=True` → 记 `hinted`，不升级。
  - `input_type != "voice"` → 记 `text_completed`，不升级独立/掌握。
  - 语义相关判定：调用统一评估（见 1.1），只有 `independent` 且满足前两条才升级；无关句/照抄不升级；无法判断记 `pending`。
- 前端队列复测：默认显示中文意图；"看答案"才显示完整句；提交带上 `attempt_key`。

### AC10-02 脱稿/换题证据（`drill_svc.py`、`schemas/session.py`）

- `submit_drill_attempt` 增加 `input_type`、`attempt_key`；`_record` 记录本次题目 `question_text`（free_speak=中文意图，transfer=换题问题）、`help_shown`、`reference_version`。
- `_judge` 拆成"按阶段题目"：`full_text/fill_blanks/structure` 对照建议句（允许词重叠作辅助），`free_speak` 对照中文意图完成度，`transfer` 对照**换题问题**（不再对照原建议句）。
- 语义判定走统一评估口径；"无法判断"→ 结果 `pending`，不写回队列、不升级阶段。
- 只有 `voice` 且 `free_speak` 成功才写 `independent`、`transfer` 成功才写 `transfer`；`text` 成功只推进展示阶段，结论记 `text_completed`，不写回队列。
- 写回队列时校验来源版本未失效（沿用 `source_invalid`）。

### AC10-03 今日复练证据（`daily_review_svc.py`、`queue/page.tsx`）

- `_item_dict` 不返回 `suggestion_sentence`，改返回 `meaning_zh` 或场景线索。
- 新增 `reveal`（看答案）落 `help_shown`。
- `submit_attempt` 增加 `input_type`、`attempt_key`；`help_used` 改为服务端 `help_shown` 派生；`attempt_key` 幂等（同键不重复生成尝试、不重复推进）。
- 判定同上：语音 + 相关 + 无帮助才 `independent` 并推进间隔；文字/有帮助/无关只记完成但不推进独立。
- `start_daily_review` 的待练集合变化时的"另建会话"问题，用 `attempt_key` 与到期集合快照去重。

### AC10-04 回顾口径（`review.py`）

- `improvements[:3]` → `[:2]`；`dedupe_improvements` 的 `[:3]` → `[:2]`。
- `_ratings`：goal 独立不再把 `vocabulary/grammar` 自动置 `adequate`，改为 `not_evaluated`（无证据不推断）；仅 `communication` 反映任务完成。
- 每条建议保留来源 `turn_id`；无证据时不展示分项评级。

### AC10-05 发音证据（`practice.py`、`schemas/session.py`、routes）

- `_parse_ise_xml` 增加词级节点解析：提取每个词节点的 `word`、`total_score`、原始位置（`beg_pos/end_pos`），最多取 3 处低分项返回 `word_items`；无词节点则 `word_items=[]`。
- `parse_result` 返回 `word_items`（保留原 `score/dimension`）。
- 新增 `POST /sessions/{sid}/turns/{turn_id}/pronunciation/dispute`：用户对发音反馈争议；争议标记后该证据不进入语块卡/待复练/记忆（沿用来源失效规则）。
- `MockPracticeEvalProvider` 保持 `word_items=[]`（零容忍无证据词级）。

### AC10-06 录音对比与版本绑定（`session_svc.py`、`practice.py`）

- `submit_practice` 评测失败时**不清理**本人录音，保留 `recording_url` 供当前卡对比；只在会话结束/用户主动删除时清理。
- 评测结果绑定 `reference_version`（参考句版本）与 `recording_version`（重录计数）；重录后旧评分不冒充新结果（旧评分标失效）。
- 前端当前卡：评测失败显示"无评分"，但示范与本人录音仍可播放。

### AC10-07 幂等（`session_svc.py`、`schemas/*`、routes）

- 创建会话、提交文字/语音回合、跟读、脱稿尝试、今日复练尝试、复测，各接收客户端生成的 `request_key`（UUID）。
- 服务端按 `(user_id, request_key)` 持久化去重：相同键相同内容返回首次结果；相同键不同内容返回 409。
- 用数据库唯一约束兜底并发（`request_key` 列唯一 + 先查后插 + 捕获冲突）。

### AC10-08 处理中退出/恢复（`session_svc.py`、前端对话页）

- 会话增加 `in_flight` 标记：处理中可调 `pause`/`end`，`end` 置终态并把 `in_flight` 持久化；迟到结果检测到终态即丢弃（不写教学/复练证据、不重复计费）。
- 服务端增加空闲收尾：会话 `active_since` 超过时长上限（含暂停时间排除）后，下次访问或定时任务主动 `ENDED`。
- 前端 `busy` 时不禁用"暂停/结束"，只禁用"重复提交"；刷新时从服务端读真实 `in_flight`/`status`。

### AC10-09 记忆来源（`memory.py`、`entities.py`、routes）

- `Memory` 增加 `source_turn_id`、`version`、`expires_at`（单条 30 天）。
- `generate_candidates` 记录来源回合与版本；`delete/revise` 一个来源后重算 `evidence_count` 与合并状态（不再"删整会话"粗放处理）。
- `get_usable_memories` 只返回未过期且与当前任务 `scene_id/goal` 相关的记忆（相关性用确定性关键词，real 用轻量判断）。
- 过期记忆在读取时过滤，并在清理任务中删除。

### AC10-10 预算（`budget.py`、`entities.py`）

- `BudgetLedger` 增加 `(scope, scope_key)` 唯一约束；`_row` 改用"先查 + 冲突捕获 + 唯一约束"。
- `settle` 拆成 `settle_estimate`（沿用固定单价入 `estimate_spent`）与 `settle_actual`（供应商实际用量入 `actual_spent`）；重试费用单独可追溯（`actual_spent` 累计真实调用）。
- `reserve` 保持条件更新 + rowcount 校验的原子性；并发下唯一约束保证不重复建行、不越限。

### AC10-11 身份/脱敏（`auth.py`、`quality_label.py`、`main.py`）

- 演示邀请码注入改为受控：仅 `SEED_DEMO_INVITES=1` 时启动种子（本地开发）；生产默认不注入。
- 质检 `list_sessions` 返回的 `user_text/reply_text` 默认脱敏（掩码中间字符，保留首尾各 1 字符与长度）；仅单独授权录音可访问。
- `get_qa_user_id` 保持 `QA_INVITE_CODES` + `revoked` 校验。

### AC10-12 质检标签（`quality_label.py`、`schemas/quality_label.py`）

- `add_label` 校验：`session_id` 与 `turn_id` 必须存在且 `turn.session_id == session_id`；`issue_type` 必须在 `ISSUE_TYPES`；`conclusion` 必须在合法集合。
- 校验失败返回 404/422；标签绑定 `reviewer_id`，重复/修改可追溯（`review_version` 递增）。
