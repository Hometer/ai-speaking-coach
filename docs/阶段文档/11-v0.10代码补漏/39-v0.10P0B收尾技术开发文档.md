## 0. 范围与不做

## 1. 设计

### 1.1 语音提交端点（后端）

复用现有 ASR（`get_asr_provider().transcribe`），新增三条语音端点：

| 端点 | 行为 |
| --- | --- |
| `POST /sessions/{id}/drill-attempt/voice` | 音频 → ASR 转写 → `submit_drill_attempt(..., input_type="voice")` |
| `POST /review-queue/daily-review/{id}/attempt/voice` | 音频 → ASR → `submit_attempt(..., input_type="voice")` |
| `POST /review-queue/{item_id}/retest/voice` | 音频 → ASR → `submit_retest(..., input_type="voice")` |

音频读取上限沿用 `max_audio_mb`（接口最多读上限+1 字节，服务层拒绝超限）。

### 1.2 前端录音复用

`practice/[sessionId]` 的 `toggleRecord("answer")` 已实现录音→上传。抽一个通用 `recordVoice(endpoint)` 辅助，用于脱稿/今日复练/复测录音提交。

- 脱稿卡：`free_speak`/`transfer` 阶段主按钮改"录音说出"，提交走 voice 端点；`full_text/fill_blanks/structure` 保留文字。
- 今日复练：每条加"录音回忆"按钮。
- 待复练：复测加"录音复测"按钮（文字仍可用，但只计文字完成）。

### 1.3 设备预检四项

`checkDevice` 依次检测并在准备区展示四项状态卡：

1. 麦克风权限：`getUserMedia({audio:true})` 是否成功。
2. 录音输入：是否获得 `audio` track（`MediaStreamTrack`）。
3. 音频播放：`new Audio()` + `canPlayType("audio/mp3")` 是否非空。
4. 网络连通：`GET /api/v1/scenarios` 是否 200。

任一失败给"照着做"修复提示；全部通过才启用语音入口，否则只给文字入口并说明"文字不参与发音/语音独立"。

### 1.4 帮助层级持久化

`get_session_detail` 增加 `current_help_level`（当前题 organize 层级，从 `Turn.help_level` 或会话状态读）。前端帮助面板在刷新后按此值恢复显示，不靠前端 state。

### 1.5 用量实值

`generation_call.call_generation` 返回值增加 `usage`（input/output tokens）；`DashScopeCoachProvider`/`DashScopeEvaluatorProvider` 把 usage 透传；`submit_turn` 在 `_log_event(usage=...)` 填真实 tokens 摘要；TTS 在 `_synth_and_save` 记录字符数。mock 模式填 0（不伪造）。
