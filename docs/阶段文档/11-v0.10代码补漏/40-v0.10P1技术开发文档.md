## 1. REQ-32 识别不确定性保护

### 1.1 风险判定（确定性，`asr_risk.py`）

`assess_risk(transcript) -> (level, reason_codes)`，规则：

| 信号 | 等级 | 原因码 |
| --- | --- | --- |
| 空转写 | high | empty |
| 乱码/噪声（非字母数字占比过高） | high | garbage |
| 疑似句尾截断（以 and/the/to/but/because/for/of/a/an/in 等结尾） | mid | truncated |
| 异常重复（同一词连续 ≥3 次） | mid | repeated |
| 简短有效回答豁免（yes/no/ok/sure/water/maybe 等） | low | — |
| 其他 | low | — |

简短回答豁免是硬规则：单词少本身不是错误。

### 1.2 数据模型

新增 `AsrRiskRecord`（`entities.py` + `database.py` 迁移）：

```text
id, user_id, session_id, turn_id(唯一), risk_level, reason_codes,
original_text, confirmed_text, action(none/confirm/rerecord/revise/text_fallback),
asr_rule_version, created_at, resolved_at
```

### 1.3 流程

`submit_turn`（voice 分支）在 ASR 转写后调用 `assess_risk`：

- **low**：走现有评估+教练流程。
- **mid/high**：不评估、不教练、不写独立证据；把转写暂存为"待确认"回合，返回 `{"risk_hold": true, "risk_level": ..., "turn_id": ..., "transcript": ..., "actions": ["confirm","rerecord","revise","text_fallback"]}`。

新增 `confirm_turn(session_id, turn_id, confirmed_text)` 端点：用户确认/修订后，用 `confirmed_text` 走原有评估+教练+落库流程，并写 `AsrRiskRecord` 的确认版本。用户退出或重录则不确认、不记学习失败。

### 1.4 边界

- 纯文字回答不适用风险判定。
- 风险等级不是识别准确率、不是能力分数；界面不声称"你说错了"。
- 不因风险判断新增模型调用。

## 2. REQ-33 水平与挑战分离

### 2.1 现状

`submit_turn` 已把 `level` 与 `difficulty` 分开传入教练上下文；`create_session` 已存 `level`/`difficulty`。缺口在**教练 Prompt 没有显式区分两者**。

### 2.2 改动

`coach.py` 系统提示词增加一节：

- `level`（beginner/basic/intermediate）→ 控制用词、句长、语速、必要解释；两档难度下保持相近语言复杂度。
- `difficulty`（simple/standard）→ 简单档角色更配合、卡住时简化问题；标准档角色在场景内提出合理澄清、条件变化或一项相关追问。
- 明令禁止：用更难生词/长句充当"标准"；虚构政策/故意刁难/连续多问；改变审核过的掌握标准。

后端 Mock 教练不受影响（确定性逻辑不读提示词）；真实教练提示词版本递增。

## 3. REQ-34 对话节奏与回应质检

### 3.1 教练决策优先级（Prompt）

1. 先处理用户本回合真正发出的请求（直接提问 / 请求解释 / 给出信息）。
2. 用户直接问角色时，先用经审核角色事实回答；事实不足用不捏造的说法说明边界，再至多追加一个相关问题；不得为推进子目标跳过用户问题。
3. 同一小目标连续追问须利用用户新信息或合理澄清；不得连续换词不换意。
4. 用户卡住时先使用现有四类求助或简化问题。
5. 只有独立评估器确认满足子目标后才更新完成证据；教练不得自行宣告掌握。

### 3.2 结构信号（确定性）

新增 `ConversationQualityMark`（`entities.py` + 迁移）：

```text
id, user_id, session_id, turn_id, user_direct_question(bool),
user_ask_explanation(bool), user_gave_info(bool), coach_action,
repeated_synonym_followup(bool), topic_jump(bool), subgoal_id,
prompt_version, scenario_version, created_at
```

`submit_turn` 在评估后记录：问号不一律解释为困惑，由确定性信号提示（文本以问号结尾、含 `what about you`/`what do you do`/`and you`/`how about you` 等）标记 `user_direct_question`；动作类型取教练 `action_type`。质检界面沿用既有脱敏与权限。

### 3.3 不新增情绪识别

"紧张/沮丧"只在用户明确表达时作为当前回合临时语境，不进入长期记忆或能力指标。
