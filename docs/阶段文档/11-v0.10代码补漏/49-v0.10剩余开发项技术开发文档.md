# v0.10 剩余开发项技术开发文档

日期：2026-10-15。阶段：3 正式前端。本文件在本轮业务代码修改前创建。基线：1e0b92f；依据 PRD v0.10 第 6.9、13.2～13.4、14.3～14.4 节。用户已授权先文档、再代码、最后 Git 提交。本轮不部署、不新增供应商、不调用付费模型。状态：本轮确认的剩余开发项已编码并通过本地回归，真实验收仍待验。

## 范围和推荐实现

1. 个性化回顾。复用每回合独立评估的结构化反馈，保存原文片段、具体问题、中文解释、建议表达、来源版本和反馈来源；结束时确定性聚合，最多两条。不额外增加总结模型调用。没有可靠反馈时显示未评价，不把场景参考句当作用户错误诊断。Mock 只返回明确固定样例反馈；旧数据无新证据时保留历史并标记旧版。
2. 产品指标。补场景选择、问卷、阶梯展示/开始、恢复尝试与设备预检关联，复用已有会话、回合、队列、评测、质检事实；在质检工作台展示每项分子、分母、未知数、口径和观察范围。
3. 前端补回顾问卷、指标展示与必要采集；已有视觉、邀请码、数据库与接口继续使用，不更换技术栈。

## 回顾证据与失败规则

- 评估器新增可选 feedback 列表，最多两条；每条为严格结构，问题类型仅 grammar/vocabulary/expression，原文片段必须出现在本次回答中，修改建议不得引入新的数字或个人事实。没有把握就返回空列表。
- 反馈单独落入评估记录，绑定 turn_id、revision_version、feedback_version。回顾只读取当前版本、未修订/争议的有效证据；能定位原回合。语法/词汇无证据时继续未评价，目标完成不推导语言能力达标。
- 模型输出缺字段、类型错误、无法对齐原文、空改写或明显新增事实时丢弃该反馈，不能回退为通用“你错了”。评估器原有超时、有限重试与结构校验继续生效。
- 固定 Mock 样例只验证存储、聚合、来源失效和界面，不用于证明真实反馈准确。旧会话不在读取时调用模型或改写历史。

## 指标口径

统一返回 numerator、denominator、rate（无分母为 null）、unknown、basis。默认观察最近 30 天，可按起止日期查询；时间为 UTC，界面显示范围。专用质检账号排除在受邀学习者统计之外。历史没有采集的新事件不补造，报告可观测样本范围。北极星沿用首练结束后满 7 天的唯一用户窗口，并单列未满观察期人数。

| 指标 | 分子 / 分母与约束 |
| --- | --- |
| 场景选择后开始率 | 选择记录成功关联普通会话的用户 / 选择过场景的用户；唯一用户，失败/放弃选择保留分母 |
| 首练完成率 | 首个普通会话有效完成的用户 / 首个普通会话已开始的用户；空结束不算完成 |
| 回顾查看率 | 有查看事件的有效完成普通会话 / 有效完成普通会话；同会话多次查看只算一次 |
| 反馈有帮助率 | 有帮助答复 / 有帮助与帮助不大答复；无法判断单列；问卷回复率另按已回复会话 / 展示问卷会话报告 |
| 7 日主动有效复练率 | 沿用已有唯一用户与 24 小时～第 7 天口径，排除文字、跟读、安排任务与窗口外回答 |
| 完整场景复练率 | 至少 3 个有效非跟读语音回答且有效说话累计 ≥60 秒；与北极星分开 |
| 到期复测完成率 | 窗口内到期且有效完成的到期项目 / 有效到期项目；文字/提示单列，不冒充独立掌握；失败和退出不移走分母 |
| 脱稿完成率 | 按展示、开始、有效尝试三个层次分别给计数与相应完成比例；同会话同阶段去重 |
| 换题迁移完成率 | 窗口内成功迁移的唯一用户 / 接受过换题任务的唯一用户，以及 / 窗口内满足脱稿条件的全部符合资格用户；分别报告 |
| 今日复练完成率 | 所选项目均有效完成的组合任务用户 / 开始过组合任务用户；跳过、退出和服务失败保留分母 |
| 词级反馈争议率 | 对词级反馈提出争议的评测回合 / 有合法词级项目的评测回合；无词级不入分母 |
| 处理中恢复成功率 | 原已受理请求结果可恢复的操作 / 发起恢复的未决操作；按操作去重，pending/uncertain/failed 单列，不将“待核对”算成功 |
| 设备预检后录音成功率 | 通过预检且形成有效语音回答的预检记录 / 通过四项预检并实际发起录音的预检记录；权限请求前记录尝试，取消、退出和失败保留分母；从未尝试录音的纯文字练习不入分母 |

上述新采集口径用于可回算的代码实现；没有真实内测样本时不展示“达标”。来源删除/修订/争议后重算有效分子，问卷随所属会话清理；产品事件不复制正文、音频或密钥。

## 数据和接口契约

- 增量增加评估 feedback_json、版本字段，会话的 selection_id/device_check_id；新增最小产品事件、回顾问卷和恢复尝试记录。唯一键保证同意图去重；已有数据不清空，迁移可重复运行。
- POST /users/me/product-events：白名单动作及有限 ID/枚举字段；客户端不能提交“完成”“独立”“恢复成功”等事实，服务端从业务表判断。返回 recorded 与 event_id；同键不同内容 409。
- POST /sessions/{id}/review-survey：shown 或 helpful/not_helpful/uncertain；只可操作自己的有效回顾，回答可修改但只保留一份当前结果及版本。
- POST /sessions/{id}/recoveries：绑定本人的既有 RequestOperation，重复恢复同操作不增加分母；GET 返回状态，不重新执行供应商调用。
- POST /sessions/{id}/turns/{turn_id}/pronunciation-dispute：仅接受本人有词级证据的评测回合，返回 disputed/turn_id，重复只计一次；无词级返回 NO_WORD_EVIDENCE，不能用总分构造争议分母。
- GET /qa/learning-metrics：仅审核员，保留现有北极星字段并新增带分母的指标对象、范围与版本。普通用户无权查看全局指标。
- 创建普通会话支持可选 selection_id/device_check_id，并在后端校验归属、有效场景和预检时间。旧客户端不传仍可用，缺少关联的旧样本报告未知而非伪造。
- 错误统一 {error:{code,message}}，不泄露堆栈；已有 SSE done/error 收尾规则保留。

## 开发与验证顺序

A. 评估反馈 schema→原回合持久化→回顾聚合→前端展示；B. 事件/问卷/恢复模型与权限接口→指标回算→前端采集和质检指标；C. 集成故障与来源失效回归→前端类型/Lint/组件/构建→隔离 Mock 浏览器与实际重启→密钥扫描→更新 README/项目状态/证据→提交。

重点反例：两种错误得到不同建议；正确或无证据回答不能被固定模板纠错；反馈伪造原文/新增数字被拒；刷新重放不重复计数；放弃/失败不消失；问卷未知不当好评；恢复 uncertain 不当成功；跨用户与客户端伪造完成拒绝；删除/修订后统计回算。
