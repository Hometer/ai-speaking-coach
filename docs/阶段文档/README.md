# 阶段文档归档规则

> 本目录存放各阶段的开发 / 修复 / 适配类产出文档。为控制单目录文件数量，按「开发逻辑 · 版本 · 修复问题」拆成子文件夹。**新文档一律按本规则归档，不要平铺在 `docs/阶段文档/` 根目录下。**

## 子文件夹与归档对象

| 文件夹 | 放什么 | 当前文件（全局序号） |
| --- | --- | --- |
| `01-阶段0-1准备/` | 阶段 0 PRD 体检、阶段 1 技术适配的产出 | 00 PRD补全清单、01 技术适配声明 |
| `02-阶段2后端MVP/` | 阶段 2 后端 MVP 的架构方案与子阶段开发文档 | 02 Harness架构方案、03~05 阶段2.1~2.3 |
| `03-阶段3前端/` | 阶段 3 前端（含期间的真实接入）适配声明与子阶段文档 | 06 前端适配声明、07~10 阶段3.1~3.4、22 阶段3.5 |
| `04-v0.5差距修复/` | v0.5 差距清单的修复批次（P0 / P1） | 11~15（P0-A / P0-B / P1-A / P1-A收尾 / P1-B） |
| `05-严重缺陷修复/` | 严重缺陷检查报告的 F 批次修复 | 16 F01-F04、17 F05-F08 |
| `06-v0.6功能开发/` | v0.6 增量需求的功能开发文档 | 18 差距梳理、19 四类求助、20 练这一句、21 数据边界 |

## 新文档归档规则

1. **先归类**：看它属于哪个「阶段 / 版本 / 修复批次」，放进对应子文件夹；没有现成子文件夹的，新建 `NN-名称/`，序号在现有基础上顺延。
2. **文件名加全局序号**：`NN-简短名称.md`，`NN` 全局递增（当前已用到 22）。序号保证任何文件在时间线上位置唯一、可排序，跨文件夹也能看出先后。
3. **目录边界**：PRD 本体只进 `docs/PRD/`；竞品扫描等背景进 `docs/调研/`；缺陷报告与差距清单进 `docs/质检/`；证据包进 `docs/evidence/阶段N/`。本目录只放「开发 / 修复 / 适配」文档。
4. **移动后查链接**：任何文件移动 / 改名后，全仓搜索引用它的 markdown 路径，同步更新，保证无断链。
