# v0.7 P0 多场景收口修复开发文档

> 依据：PRD v0.7（6.2/6.4/6.5/6.7/6.8/8.1/9.1）、产品经理 2026-09-22 批次的已确认问题清单。
> 状态：修复方案稿。本批只收口多场景主路径，不开发待复练队列/进步中心/七日计划/质检工作台，不调用真实付费模型（保持 PROVIDER_MODE=mock）。

## 1. 范围与目标

上一批只完成了「场景列表 + 目标 + 开场问题」的切换，后续追问、求助、完成判断、回顾、历史仍残留英文面试。本批把七个场景从头到尾真正场景化：

- 场景配置补齐 PRD 要求的完整字段，并成为教练、评估器、求助、结束判断、回顾的唯一事实来源。
- 完成判断从固定 `intro/followup` 两字段，改为「每个场景从配置读取自己的子目标与完成条件」。
- Mock 教练、Mock 评估、回顾、历史、再练一次全部按场景返回确定性结果。
- 英文面试保持原有行为，不被其它场景改动破坏。

## 3. 数据变化

- `Session.subgoals`（JSON）语义从固定 `{"intro","followup"}` 改为「场景配置的 subgoal key 列表」；状态仍为 `{"status":"","evidence":[]}`。
- 场景配置 `SCENARIOS` 每个场景新增：`subgoals`、`acceptable_points`、`follow_ups`（各 subgoal 的追问）、`help_materials`（关键词/半句/完整示例）、`reference_expressions`、`variations`、`stop_conditions`、`completion_criteria`。
- `SessionListItem` 响应新增 `scene_id`、`scene_label`。
- 数据库表结构不变（subgoals 仍是 Text JSON，scene_id/scene_version 已有）。

## 4. 接口变化

- `GET /api/v1/sessions`：列表项新增 `scene_id`、`scene_label`。
- 其余接口路径不变；`POST /sessions` 已支持 `scene_id`。
- `GET /sessions/{id}` 已返回 `scene_id`、`scene_label`，本批前端开始使用。

## 5. 关键实现约定

1. **子目标通用化**：`_load_subgoals(session)` 按 `session.scene_id` 取场景 `subgoals` 初始化；`_current_subgoal` 返回第一个未 `independent` 的子目标；全部 `independent` 视为 `goal_reached`。
2. **Mock 教练按场景**：`decide(context)` 的 `context` 增加 `scene_id`、`subgoal`、`follow_ups`、`reference_expressions`；追问与跟读建议从场景配置取，不再写死 experience/software development。
3. **Mock 评估按场景**：`evaluate(context)` 增加 `acceptable_points`（来自场景配置），命中关键词或答案足够长判 `independent`；默认保留面试关键词以兼容原有测试。
4. **回顾按场景**：`build_review` 读场景的 `reference_expressions` 生成 `practice_sentence`，`next_suggestion` 用场景 goal；材料不足减少建议，不生成无依据内容。
5. **再练一次沿用场景**：历史页 `retry(scene_id, difficulty)` 传原场景与原难度。

## 6. 验收用例（本批必须通过）

- 酒店入住：确认预订 + 询问服务后，追问/求助/完成判断/回顾保持酒店场景；页面与历史显示「酒店入住」；内容不出现 experience / software development。
- 会议中表达意见：观点+理由后教练围绕观点追问；完成判断用观点/理由，不套自我介绍。
- 认识新朋友：按配置完成两轮简单交流；一段长回答不能绕过两轮要求。
- 英文面试：原有行为继续可用。
- 历史与恢复：刷新练习页场景/目标/对话/状态一致；历史显示真实场景；再练一次创建同场景；结束后迟到响应不重开。
