# v0.7 P1 跨日约束修复开发文档（AC07-08）

> 依据：PRD v0.7 6.8（REQ-23）、PRD v0.8 0.3 / 14.1（AC07-08）、现有代码。
> 状态：修复方案稿。本批只修到期校验，不扩范围、不重写队列。

## 1. 问题与根因

AC07-08 要求：两次独立成功至少间隔 24 小时，才能标记已掌握。

当前 `review_queue.submit_retest` 在第一次独立成功后写入 `due_at = now + 24h`，但**第二次提交时没有校验 `due_at`**，导致连续提交两次会立即 `mastered`。现有测试允许这种连续提交，不能视为 AC07-08 已通过。

## 2. 修复方案

在 `submit_retest` 增加到期校验：

- 当队列项处于 `awaiting_retest`（已独立成功一次、等待复测）且 `due_at` 未到时，返回明确错误（`NOT_DUE`，409），**不增加成功次数、不改状态**。
- 到期后（`now >= due_at`）才允许复测推进。
- 时区处理：`due_at` 若无时区信息按 UTC 补齐，避免比较出错。

## 3. 数据 / 接口变化

- 无表结构变化。
- 接口 `POST /review-queue/{id}/retest`：未到期时返回 `{"error":{"code":"NOT_DUE","message":"复测尚未到期，请稍后再试"}}`，状态码 409。

## 4. 验收用例

- 第一次独立成功后，立即再次提交 → 返回 409，`success_count` 保持 1。
- `due_at` 推进到过去后再次提交 → 正常推进，两次独立成功才 `mastered`。
- 原有测试不删除、不放宽，测试总数只增不减。

1. 后端全部 Mock 测试（原 71 项只增不减）。
2. 前端不受影响（无需改动）。
