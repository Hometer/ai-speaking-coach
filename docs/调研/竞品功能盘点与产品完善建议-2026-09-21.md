# AI 口语教练竞品功能盘点与产品完善建议

调研日期 2026 年 9 月 21 日  
判断基线 当前主分支 `4f415e5`、PRD v0.6、现有前后端代码与 51 项后端回归测试  
用途 供产品经理决定下一批范围，不代表已经批准开发

## 这次盘点得到的判断

项目已经有一条完整的单场景训练链路。用户能用邀请凭证进入，选择水平、难度和时长，用语音或文字回答；教练可以追问、给四类帮助、安排跟读和复测；结束后还有回顾、历史、单句复练和可关闭的学习记忆。现有能力已经超过仓库里几份旧文档所写的状态。

接下来最该做的是把这条链路用真实用户和真实服务验清楚。教学判断是否可靠、普通回合是否够快、一次练习到底花多少钱，这三件事尚未形成准入证据。此时大量增加场景、课程、数字人和游戏化，会让问题更难定位，也会把内容与质检工作一同放大。

通过当前内测闸门以后，下一批最值得增加的是进步看板、面试子场景和基于错误的专项复练。这三项都能接住现有回顾与记忆，也直接服务 7 日主动有效复练率。实时视频、AI 头像、排行榜、考试估分和完整课程体系继续后置。

## 仓库检查范围

本次清点了 143 个纳入范围的项目文件，其中包括 54 份 Markdown、40 个 Python 文件、8 个 TSX 页面或组件、3 个 TypeScript 文件、样式、配置和 19 张验收图片。详细阅读覆盖 PRD、项目状态、阶段文档、前后端源码、接口、数据模型和测试。验收图片按对应证据包核对用途。

`node_modules`、`.next`、`.venv`、`.git`、运行数据库、缓存、构建产物和本地密钥文件没有进入功能判断。它们属于依赖、生成内容或敏感数据，逐文件阅读不会增加产品结论，还可能把本地凭证带入报告。

后端 Mock 回归在本次检查中重新运行，结果为 51 项全部通过。这个结果能证明已写入测试的状态与边界，不能替代真实教学、真实语音、真实时延和费用验证。

## 现有链路还没收好的地方

这些问题比增加竞品功能更靠前。

| 问题 | 代码或文档现状 | 建议 |
| --- | --- | --- |
| 真实教学质量 | PRD 要求误纠错率和错误独立完成率都不高于 5%，每类至少人工抽查 30 条；目前仍待验 | 多人测试前完成受控抽查，先修误判，再扩场景 |
| 时延与费用 | PRD 要求至少 200 个普通回合并报告 P50、P95、失败和费用；目前没有这份证据 | 做一页内部质量看板，按真实与 Mock、语音与文字、模型版本分开 |
| 手机录音 | 桌面和响应式页面已查，手机真机麦克风仍待验 | 增加开始前的麦克风、扬声器和网络自检，给出文字降级入口 |
| 跟读反馈太薄 | 前端只显示一个总分，没有单词或音素问题，也没有本人录音与示范的并排对比 | 先验证讯飞细分结果可信，再显示最重要的一到两处问题 |
| 历史用途混淆 | 列表接口没有返回 `practice_type`，单句复练会被页面统一写成英文面试 | 历史列表区分完整面试和单句复练，统计也分开 |
| 再练一次丢设置 | 历史页重新开始时固定用基础档和 5 分钟，只沿用难度 | 接口返回并沿用原水平、难度和用户当前默认时长 |
| 历史页少一个动作 | 历史详情能看到建议句，却要再打开完整回顾才能“练这一句” | 在有效建议旁直接放入口，继续保留材料确认 |
| 记忆更正没有前端入口 | 后端已有修改记忆接口，页面只能删除 | 给候选记忆增加编辑与确认，避免用户只能删掉重来 |
| 文本保留期未自动执行 | 文档写会话文本保留 30 天，代码目前只自动清理上传录音 | 上线前补文本到期任务、删除记录和失败重试 |
| 暂停计时不精确 | 后端暂按开始时间计算墙钟，暂停时间也会被算进去 | 改成累计非暂停时长，并保留计时依据 |
| 前端自动化不足 | 目前没有前端单元或端到端测试脚本 | 至少覆盖登录、首练、四类帮助、结束回顾、删除和刷新恢复 |
| 文档状态互相冲突 | `v0.6差距梳理.md` 仍写三项核心增量未实现，前端适配声明仍写无邀请码和讯飞待接，项目状态又把已修的 F-05 至 F-08 列为剩余项 | 开下一批开发前统一修订，后续只让状态文件指向最新基线 |

## 哪些功能要加

| 建议 | 功能 | 判断依据 | 进入条件 |
| --- | --- | --- | --- |
| P0 先做 | 内部质量与运营看板 | 当前已经记录事件，却没有可直接评审的错误、耗时、费用、帮助漏斗和复练漏斗 | 接真实内测前完成 |
| P0 先做 | 设备与权限自检 | 录音是首条链路的入口，真机失败会直接拉低首次完成率 | 手机 Chrome、Safari 都能看到麦克风、播放和文字降级结果 |
| P0 先做 | 收好现有缺口 | 历史用途、复练设置、记忆更正、文本到期和暂停计时都属于已有承诺 | 现有 PRD 回归无阻断项 |
| P1 建议做 | 个人进步看板 | Speak、ELSA、Loora、SpeakGuru 都提供进度；当前页面只有记录数和回答轮次 | 只展示有证据的趋势，文字、跟读、独立回答分开 |
| P1 建议做 | 面试子场景包 | 当前只有自我介绍，内容很快耗尽；增加同一目标内的新题能检验迁移 | 先做 5 至 8 个职场面试任务，不开放无限生成 |
| P1 建议做 | 错误驱动的专项复练 | 现有回顾、记忆和“练这一句”已经提供数据基础 | 一条弱项至少有两份独立证据，用户可跳过和删除 |
| P1 建议做 | 更具体的发音反馈 | 同类普遍提供单词、音素、重音或流利度反馈；当前只有总分 | 先完成人工对照，低置信度时只给重试，不给断言 |
| P1 建议做 | 轻量自适应校准 | Loora、ELSA、Praktika 都先判断水平；当前完全依赖用户自选 | 用首两轮表现建议调档，用户确认后生效，不增加长考试 |
| P2 观察后做 | 表达收藏 | 同类常见，PRD 也已列为候选 | 内测中确实出现复制、回看或保存需求，再定义保存和删除 |
| P2 观察后做 | 自定义岗位与场景 | Speak、ELSA、Praktika 都有自定义内容 | 固定面试子场景的质量和成本先达标，首版只收岗位和目标，不上传真实简历 |
| P2 观察后做 | 多口音和语速 | 对中国成人职场场景有实际价值 | ASR 对合理口音的误判率先通过人工质检 |
| P2 观察后做 | 自由对话 | 市场上很常见，也容易变成普通聊天机器人 | 单场景 7 日有效复练率达到目标，再用小入口测试 |
| 暂不做 | 视频通话、数字人、全双工插话 | 成本和复杂度高，对当前核心指标的帮助尚无本项目证据 | 等回合制体验证明价值后单独立项 |
| 暂不做 | 排行榜、连续签到、社交 | 它们可能提高打开次数，也可能把测试用户推成任务行为，污染主动复练指标 | 先验证自然复练，再考虑轻提醒 |
| 暂不做 | 雅思估分、CEFR 认证和就业结论 | 需要专门题库、标定、人工对照和责任边界 | 有独立测评项目和专家负责人后再做 |
| 暂不做 | 多语种、儿童、企业后台和支付 | 都会改变目标用户、内容、安全或商业范围 | 当前成人英语面试方向验证后另写 PRD |

## 公开竞品很少讲清的功能

这些模块更适合成为项目自己的长处。它们大多能复用现有数据和规则，开发规模也小于扩成一个完整课程平台。

### 帮助有效性

现在已经能分清用户是没听清、没听懂、不会组织，还是想把中文换成英文。下一步应记录每次帮助有没有被看到、播放和采用，用户随后有没有继续开口，换一道相近问题后还能不能独立完成。产品经理最后能看见哪种帮助真有用，哪种帮助只让页面多了一条消息。

### 反馈证据

每条改进建议都显示它来自哪次回答、系统看到了什么、建议改哪一点。用户修订转写或标记有误以后，旧判断、单句练习和记忆一起失效。现有后端已经做了大半，前端还可以把这条证据关系讲得更明白。

### 迁移验证

用户读对一句参考答案，只能说明这次模仿完成。系统随后给一个相近的新问题，观察他能不能在没有参考文本时说出来。这块与项目现有的独立完成定义很合，也比单纯刷分更能说明训练有没有留下东西。

### 低压力开口

记录用户从页面可用到第一次有效语音用了多久，卡住以后是否愿意继续，帮助是太早还是太晚。页面可以允许更长思考、先说关键词、切到文字再回到语音。这里不做心理诊断，只观察产品有没有帮用户迈过第一次开口。

### 内容与质检后台

面试材料需要版本、适用水平、目标、替代追问和回归样例。内部审核员还需要抽样、标错、记录分歧和回看同一标准版本。这个后台不会出现在用户首页，却决定了以后每加一个场景要付出多少审核成本。

### 数据使用说明

历史、学习记忆、一次性单句材料和质检录音是四种不同用途。设置页可以告诉用户每种数据保存多久、当前是否开启、删除会影响什么，并让用户直接处理。现有产品已经有较好的边界规则，清楚展示以后会比一段笼统的隐私说明更有用。

## 推荐的产品顺序

### 当前批次

暂停新增面向用户的大模块。先把真实质量、时延、费用、手机录音和已有数据边界验完，同时补齐历史分类、复练设置、记忆更正、文本到期和前端主链路测试。15 名成人受邀用户按 PRD 分三档进入，真实服务和 Mock 结果分开记录。

### v0.7

增加个人进步看板和 5 至 8 个面试子场景。首页仍保持一个主入口，系统根据上次证据推荐下一题。用户也可以自己选择，不强制按计划走。

### v0.8

增加错误驱动专项复练、细分发音反馈和轻量调档建议。此时再观察表达收藏是否真的有人需要。收藏若进入开发，要和长期记忆分开，保存与删除规则单独写清。

### 后续试验

只有 7 日主动有效复练率、反馈有用度和误判指标同时站住，才小范围测试自由对话或自定义岗位场景。数字人、实时视频、游戏化和考试估分继续单独立项，不能混在一次普通迭代里。

## 产品定位建议

现阶段适合把产品讲成“会在你卡住时给适量帮助，并确认你能否在新问题里独立说出来的面试口语教练”。这句话与已经实现的四类求助、单句复练、迁移判断和可控记忆相符，也避开了和大厂比课程数量、头像数量与语言数量。

下一次范围评审只需要定两件事。第一件是是否按 P0 收口后再进入 v0.7。第二件是 v0.7 的面试子场景先覆盖哪些职场任务。建议优先选择项目经历、冲突处理、优势与不足、离职原因、职业规划和反问面试官，并从中取 5 个做首批。
